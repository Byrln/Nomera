# Dashboard and Tours/Departures — local implementation report

Verified 12 September 2026. The approved Shopify direction is implemented with source-owned shadcn primitives. Phase 2 core workflows are implemented locally; binary media uploads remain unfinished. No commit, push, deployment, or remote database mutation was performed.

1. **Routes.** Authenticated `/dashboard`, `/tours`, `/tours/new`, `/tours/[tourId]`; GET `/api/dashboard`, `/api/tours`, `/api/tours/[tourId]`. Navigation includes only implemented destinations. Root and tour error boundaries provide localized retry controls.
2. **Components.** Reused NOMERA Button, Input, Card and Badge; added official shadcn Sidebar, Chart, Table, Field, Select, Checkbox, ToggleGroup, Collapsible, Empty, Alert, Progress, Skeleton, Item, Tooltip, Sheet, Textarea, Tabs, Dialog and Pagination dependencies. Product controls and data displays use these primitives. Raw HTML remains for semantic structure, text, layout, hidden fields and primitive internals. See `2026-09-12-shadcn-sources.md` for provenance and adaptations.
3. **Domain and services.** Dashboard metrics use actual tenant records and explicit period/currency definitions. Tours support search, status/category/destination filters, pagination, creation, editing, itinerary, HTTPS image references, departure dates/capacity/prices/status, publication snapshots and guarded archive. Publication does not change when a draft is edited. Monetary formatting preserves integer minor units exactly.
4. **PostgreSQL and authorization.** Migrations 0002 and 0003 extend the existing Railway PostgreSQL architecture. Repositories authorize current session and tenant membership, check capabilities, validate payloads, enforce optimistic versions, reuse idempotency operations, and write audit records transactionally. Capacity guards protect reserved travelers. Tests use a separate loopback PostgreSQL 18.4 instance and isolated schemas. Migrations were also exercised on a disposable named local preview database.
5. **Repository/configuration.** Bun and committed lockfile only. Existing environment files and unrelated work were preserved. The optional `NOMERA_LOCAL_QA=1` selects ignored `.next-qa` output so QA development can coexist with the user's running development server. Final preview runs the production build on loopback port 3102.
6. **Behavior and security coverage.** Schema/domain tests, tenant authorization, auth actions, API routing, SQL integration, mutation validation, publication/archive/capacity rules, exact money formatting, and recovery control gating are covered. Draft recovery is scoped to verified user, tenant and tour. Sign-in and sign-out clear tour drafts; workspace changes retain scoped drafts. Recovery requires explicit Restore/Discard before editing.
7. **Browser evidence.** Rendered screens and viewport screenshots were inspected through Chrome. Dashboard, catalog and editor were exercised at 320, 375, 414, 768, 1024 and 1440 pixels across Mongolian/English and light/dark samples. Page overflow was checked; wide data tables scroll within their own container. Browser interactions verified dashboard filtering/comparison/chart/table, mobile navigation and Escape, tour creation/save/itinerary/publication, departure creation, archive blocking, invalid image references, search-empty/reset, and persisted reload. Unsaved navigation Cancel, browser Back recovery, Restore, and explicit Discard all passed. Screenshots were inspected in-session, not exported as permanent artifacts.
8. **Visual differences and fixes.** Retained NOMERA fonts, tokens and travel terminology while adopting Shopify's compact shell, status tabs, filters and dense tables. Removed custom control replacements. Fixed mobile date-field width, dashboard flex overflow, chart tooltip overflow after resizing, wrapped tab height, theme-button contrast and registry state selectors. Motion remains targeted and respects reduced motion; no GSAP dependency was added.
9. **Limitations.** Media currently accepts validated HTTPS image references with alternative text. Binary uploads, storage ownership/visibility/checksums and lifecycle integration from the full roadmap are not implemented. No public storefront, booking/customer write workflows or subsequent roadmap phases were added. Preview records are clearly local synthetic QA fixtures; several legacy seeded departures already exceed capacity and are displayed truthfully. Auth/session-expiry and stale-write failures have automated coverage, but were not all fault-injected in this final browser pass. Hosted production behavior is unverified.
10. **Mobbin.** Initial rate limit was followed by successful current-task research and visual inspection. Approved [Shopify Analytics](https://mobbin.com/screens/12055258-4e17-45cc-af1f-2a65561ac626), [Orders](https://mobbin.com/screens/b743aa06-5d21-485f-8d69-d5f0052727c5), and [Products](https://mobbin.com/screens/e8786dbf-4443-40f1-91f1-c45d3560aa80) informed hierarchy, density and interaction patterns. Unrelated commerce columns and invented metrics were rejected.
11. **21st.dev.** Current-task MCP research inspected Origin UI Table demo 96 and Table Edit demo 7457 source/dependencies. [Origin UI Table](https://21st.dev/@originui/components/table) informed composition. Existing/source-owned official shadcn primitives were selected; demonstration fetches and additional chart stacks were rejected.
12. **Lint and design checks.** `bun run lint` passed inside the final `bun run check`. Actual Tastemaker anti-slop scan passed across 15 files; motion audit passed across 14. Hallmark/Tastemaker/GPT Taste review informed the rendered fixes. Computed primary text/control contrast pairs range from 6.68:1 to 16.57:1; this is not a claim that every possible color pairing was audited.
13. **Types.** `bun run typecheck` passed for the workspace.
14. **Tests.** Final `bun run check` passed 137 tests: schemas 23, domain 24, PostgreSQL 24, and root/admin behavior 66. PostgreSQL tests actually ran against local PostgreSQL, including 16 dashboard and 6 tour SQL integration tests; they were not skipped for missing configuration. A production-only currency whitespace hydration mismatch was reproduced from the actual server response and Chrome DOM, fixed with consistent supported-locale spacing, and covered by a failing-then-passing regression.
15. **Build.** Final `bun run build` passed for admin and storefront through `bun run check` (exit 0). The final admin build includes all listed routes. The rebuilt production catalog was reloaded and visually inspected with no new application console errors or warnings; browser extension warnings were excluded. Temporary viewport/reduced-motion overrides were restored. This proves local verification, not deployment.
